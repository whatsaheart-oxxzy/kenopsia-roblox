# QA — P4.1 SORTING FLOOR (23.08.2026)

First trial built on the MP framework (TrialKit / TrialClientKit). Four files:
`Services/SortingFloor.luau`, `Shared/Rules/SortingFloorRules.luau`,
`TrialClients/sorting.luau`, `tests/sorting.lua` (34 checks). `MachineFlow.TRIALS.sorting.ready = true`.

## Design as built (docs/MP-04 §12)

* 8 item kinds × 4 colours × sealed/open; rules are predicates → chute A, else B; 7 single-attribute
  rules, 4 two-attribute rules (round 3, or the last round of a shorter session).
* Seeded per room+round: the rule schedule (first rule on the board at `begin`, then 8–12 s apart,
  never the same twice, 0.5 s Hazard telegraph on the board before every change) and the item stream
  (LEAD 2 s, window 1.6/1.3/1.0 s by round, gap 1 s, same count per station).
* Server-clock validation: `sort {itemId, chute}` / `pass {itemId}` only for an undecided item of the
  sender's own station inside its window; correct = +1, wrong = strike, 3 strikes → lamp Signal +
  0.7 s telegraph → trapdoor opens, sorter unanchored, `R:kill` "MISFILED." (gore 1.3).
* Ranking: ALIVE + (correct·10 − strikes·3), OUT + correct·10, capped 999 (item budget ≈ 16/station).
* Client: items as chunky Parts on the belt moved on server time (≤ ~17 live), board `SurfaceGui`,
  lamps flash per result, HUD = rule, timer, "AT YOUR STATION" readout in words + window bar,
  SORTED count, 3 strike dots; Q/E/Space, gamepad X/B/Y, three touch buttons; fixed station camera;
  `presentation.grade` (warm, fog 40/150) for SimulationGrade.

## Live checks (solo, Studio)

* Arena 59 static parts at `GameConfig.Arenas.Origins.sorting`; HUD in `KenopsiaTrialHud`; rule
  board text; 17 live item parts; camera fixed at (0, 19, −25); sorter anchored on Trap1.
* Items reach my station ~every 2.6 s ("BOTTLE | RED | SEALED", "PARCEL | GREEN | SEALED", …).

  cleanup. No handler errors.
* Rule rotation observed ("OPEN -> A. SEALED -> B." → "GLASS -> A. ALL ELSE -> B." → …).

## Found on the way
