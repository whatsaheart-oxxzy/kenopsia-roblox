# QA — P2.2 (part 1): CRT overlay layer + boot ledger (2026-08-22)

**Place:** Kenopsia_MainGame, Studio Play Solo, desktop 1268 × 576.

## What was built

- `StarterPlayerScripts/UiFx.client.luau` (new, Rojo-mapped) builds its own ScreenGui `KenopsiaMachine_Overlay` (DisplayOrder 60, `IgnoreGuiInset`, `ScreenInsets = None`) so nothing animated lives inside the 520-descendant `KenopsiaMachine` (whose render cache would otherwise be rebuilt per frame):
  - scanlines: one tiled `ImageLabel`, 8 × 8 uploaded tile (4 clear rows, 4 rows black @ 30 %), `ResampleMode = Pixelated`, ImageTransparency 0.35 (0.55 on Mobile so the 10-px text survives) — static;
  - vignette: four edge gradients (black 45 % → 0) — static; invisible over the near-black menu, visible over the 3D world;
  - refresh band: 110-px phosphor band, 2 s linear sweep every 10 s (8 s silence);
  - interference blip: 2-px line at a random height for 80 ms every 8–20 s.
  - Toggles: player attribute `KenopsiaCRT` (false = off), `GuiService.ReducedMotionEnabled` and `KenopsiaReduceFlicker` stop the band and the blip. The settings rows for these come with P2.3.
- `ReplicatedFirst/KenopsiaLoading`: boot ledger — `POST / PHOSPHOR / SUBJECT LINK / PROTOCOL TABLE / AUDIO BUS / SIMULATION POOL` land 120–200 ms apart, line 4 stalls 0.7 s, then the old dots loop; cut by `done` the moment the bridge drops (never outlasts the real load).
- Uploaded for later dither fades: Bayer 4 × 4 tiles 128764657994112 / 121598984043867 / 93726535183476 / 72454964162888 (levels 1–4).

## Observed

- Ledger captured live (all six lines with OK, stall on PROTOCOL TABLE) before the bridge dropped.
- Overlay present (12 descendants), scanline asset `AssetFetchStatus.Success`, `IsLoaded = true`, covers the viewport. Over the near-black Machine screens the darkening lines are not perceptible in a capture — they read over text and over the arena; band/blip raised to 0.8 / 0.45 transparency after the first capture showed them too faint for JPEG.
